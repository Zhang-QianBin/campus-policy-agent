# Excel 政策附件读取实验

本实验对应 Issue [#9](https://github.com/Zhang-QianBin/campus-policy-agent/issues/9)，使用 openpyxl 读取本地 Excel 政策附件，输出有效单元格的文字及其工作表、坐标和合并范围，为后续检索提供可追溯的原始数据。

脚本入口：[scripts/excel-reading.py](../scripts/excel-reading.py)。当前为单文件命令行实验，结果只输出到终端，不写入数据库或修改原始附件。

## 环境与依赖

已验证环境：Windows、Python 3.12.10、openpyxl 3.1.5。

在项目根目录打开 PowerShell。如果尚未创建虚拟环境，先执行：

```powershell
py -3.12 -m venv .venv
```

安装本实验所需依赖：

```powershell
.\.venv\Scripts\python.exe -m pip install openpyxl==3.1.5
```

`json`、`pathlib` 和 `zipfile` 为 Python 标准库，无需另外安装。本说明仅列出本实验依赖，公共依赖配置由工程初始化任务统一维护。

## 运行方式

在项目根目录执行：

```powershell
.\.venv\Scripts\python.exe scripts/excel-reading.py
```

查看退出码：

```powershell
$LASTEXITCODE
```

成功时退出码为 `0`，终端输出一个 JSON 对象；已处理的失败场景显示中文提示并以 `1` 退出，不输出结果 JSON。

当前没有命令行参数，需要修改脚本开头的 `excel_path` 并保存，才能切换输入文件。使用相对于项目根目录的路径，附件放在 `data/samples/<source_id>/` 下。

## 输出结构

每份文件输出一个对象：文件级信息保存在 `metadata` 中，单元格记录保存在 `records` 中。示例取自 policy-004，以下只展示第一条记录：

```json
{
  "metadata": {
    "source_id": "policy-004",
    "title": "861caa12-fe0a-4409-b03b-73d359290176",
    "file_path": "data/samples/policy-004/attachments/861caa12-fe0a-4409-b03b-73d359290176.xlsx"
  },
  "records": [
    {
      "sheet": "Sheet2",
      "cell": "A1",
      "text": "2026级卓越学院校内选拔细则和复合型双学位校内选拔细则",
      "merged_range": "A1:E1"
    }
  ]
}
```

| 位置 | 字段 | 含义 |
| --- | --- | --- |
| metadata | source_id | 相对于 `data/samples` 的第一级目录名，例如 `policy-004`；表示来源记录，同一来源可能有多个附件 |
| metadata | title | 文件名去掉扩展名，暂未识别文件内的正式标题 |
| metadata | file_path | 相对于项目根目录的文件路径，使用 `/` 分隔 |
| records 中每条记录 | sheet | 工作表名称 |
| records 中每条记录 | cell | 单元格坐标，例如 `A1` |
| records 中每条记录 | text | 单元格值转为字符串并去除首尾空白后的内容 |
| records 中每条记录 | merged_range | 所属合并区域，例如 `A1:E1`；未合并时为 JSON `null` |

文件级信息只保存一次，通过同一个结果对象追溯各条记录。Excel 使用工作表与单元格定位，不设置 PDF 页码字段。

## 读取与清理规则

- 遍历工作簿中的所有工作表，再逐行、逐格读取。
- 跳过值为 `None` 的单元格，以及清理首尾空白后为空的单元格；数字 `0` 保留为字符串 `"0"`。
- 合并区域只记录实际保存值的左上角单元格，并附上完整合并范围，不向其余单元格重复填充文字。
- 保留原文内容，不根据表格位置自行推断适用对象，也不补充原文未写出的选拔条件。
- 读取完成或读取过程中发生异常时，通过 `finally` 关闭已成功打开的工作簿。

## 失败场景与复现方法

切换输入后保存脚本，再运行上面的命令。临时文件可放在 `data/samples/policy-003/attachments/` 下，复现结束后删除，避免作为正式政策样本提交；恢复脚本的正常输入路径。

| 场景 | 复现方法 | 预期结果 |
| --- | --- | --- |
| 文件不存在 | 将路径改为该目录下不存在的 `not-exist.xlsx` | 捕获 `FileNotFoundError`，提示“文件未找到”及路径，退出码为 `1` |
| 格式不支持 | 将路径改为项目中真实存在的 PDF | 捕获 `InvalidFileException`，提示“无效的Excel文件”及具体原因，退出码为 `1` |
| 内容不是有效 ZIP 包 | 创建普通文本文件，将完整文件名改为 `invalid.xlsx` 后作为输入 | 捕获 `BadZipFile`，提示“Excel文件损坏或无法解压”及原因，退出码为 `1` |
| 工作簿为空 | 用 Excel 新建并保存一份不含内容的 `.xlsx`，作为输入 | 提示“工作簿中未读取到有效文字”，退出码为 `1` |
| 只有空白字符 | 在新建工作簿的某格输入几个空格并保存，作为输入 | 不生成空文字记录，提示没有有效文字，退出码为 `1` |
| 数字为 0 | 在临时工作簿的 `A1` 输入数字 `0`，作为输入 | 输出 `"text": "0"`，退出码为 `0` |

将文本文件改成 `.xlsx` 只用于构造无效输入，并不会把它转换成真正的 Excel 文件。`BadZipFile` 仅覆盖部分无效或损坏情况；缺少必要文件、XML 损坏等问题仍可能抛出其他异常。

| 检查项 | 结果 |
| --- | --- |
| policy-003 | 正常运行，输出 540 条记录，文字均非空 |
| policy-004 | 正常运行，输出 52 条记录，文字均非空 |
| policy-004 合并范围 | `Sheet2!A1` 为 `A1:E1`，`Sheet2!A6` 为 `null`；已核对全部记录的范围及位置无重复 |
| 缺失文件、PDF 输入 | 核对对应分支，退出码均为 `1` |
| 无效 ZIP 内容、空表、纯空白 | 使用内存构造输入验证脚本分支，均显示提示并以 `1` 退出；磁盘文件的人工复现方法见上表 |
| 数字 0 | 使用内存工作簿验证，保留为 `"0"`，退出码为 `0` |
| 原始附件 | 两份 Excel 在本轮验证前后的 SHA256 一致 |

记录数用于复现当前样本，不是所有政策文件的固定要求；输出数量也不等于政策语义或表头关联已经验证正确。

## 当前限制

- 当前只读取单份本地文件，路径在脚本内配置；尚无批量导入、统一读取函数或数据库写入。
- 当前记录是原始单元格数据，不是最终 RAG 检索片段。后续需要结合表头、行和合并说明组织上下文。
- 不执行 OCR，不读取图片中的文字；字体、颜色、批注和超链接目标等未单独提取。
- 不计算公式；当前按 openpyxl 默认方式读取，公式单元格可能输出公式字符串。
- 合并范围用于保留位置，不自动把共同条件分配给各专业。
- `title` 只是文件名回退值，policy-004 因此仍显示 UUID；来源说明中的正式名称尚未接入。
- 原文写“详见学院网站”等内容时保持原样；当前脚本不会继续访问网站或推断缺失要求。
- 当前异常处理覆盖上表所列场景，不保证识别所有损坏文件或操作系统读取错误。
