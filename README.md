# Campus Policy Agent

基于知识库的高校政策查询与更新提醒桌面智能体。

Campus Policy Agent 面向需要查询高校政策的学生，计划将分散在学校及各部门官网的政策文件、通知等整理为可检索的知识库，通过自然语言问答帮助用户定位适用条件、办理材料和时间要求，并依据用户设置的订阅条件提醒政策更新。

## 当前状态

项目处于**初始化与需求设计阶段**，正在完善项目范围和技术选型。下列功能与里程碑均为开发计划，首个可运行版本完成后将补充安装、配置和使用说明。

- **首版目标平台**：Windows。
- **目标运行方式**：桌面客户端在本地运行，问答通过模型 API 推理；具体模型服务尚待选定。
- **已确定的核心框架**：Python + LangChain，按需使用 LangGraph。

## 项目背景

学生需要在学校官网中查找相应通知，如不同学院的科研竞赛、奖学金评比等，这些通常分布在学校及不同部门的通知栏目中。但学生并不确定其关键词，通过搜索关键词查找到的内容往往冗长且命中率低。学生需要逐个查找网页、下载附件，再提取相关内容、进行核对。这样不仅费时费力，也容易遗漏后续更新。

本项目暂以杭州电子科技大学的指定公开栏目为试点，将资料采集、检索问答、原文核验和更新提醒连接起来，逐步建立可持续维护的政策查询工具。

## 计划功能

| 功能 | 说明 |
| --- | --- |
| 政策采集与归档 | 采集指定官网栏目的正文及可提取文本的 PDF、Word 附件，保存来源链接、发布日期、采集时间和可确认的适用对象，清洗去重并保留文件版本。 |
| 自然语言问答 | 检索知识库中的相关政策，结合时间、院系、年级等条件，归纳内容概览、适用条件、时间节点及所需材料等。
| 原文核验 | 展示文件标题、发布日期、原文链接和支持回答的依据片段，方便用户核对结论。 |
| 更新检测 | 按设定周期检查指定栏目中的新增文件与内容变化，保留历史版本。 |
| 订阅提醒 | 根据用户主动设置的关注主题、院系、年级等条件匹配通知，说明提醒原因，并避免重复提醒同一文件版本。 |

典型使用场景包括：

- 查询某年度、某学院推免申请所需的材料，并查看原文依据。
- 查找某项通知的办理时间和截止日期。
- 订阅与本学院、年级相关的毕业通知，在出现匹配更新时收到桌面提醒。

## 首版范围与边界

- 从**杭州电子科技大学的一个公开栏目**开始，先整理 **5–10 份政策**，验证采集、检索和附带来源的问答流程；具体栏目仍待确定。
- 优先处理网页正文和可提取文本的附件，扫描件识别（OCR）作为后续扩展。
- 资料不足、文件冲突或适用范围不明确时，说明无法确定及缺失的信息；不自动作出学生资格认定。
- 仅在原文有明确依据时判断文件替代关系，避免直接用发布日期推断旧政策已经失效。
- 更新任务在客户端运行且联网时执行，离线或休眠恢复后补采。

## 技术框架

| 层次 | 选型 | 用途 |
| --- | --- | --- |
| 开发语言 | **Python** | 实现数据采集、文档处理、检索和应用业务逻辑。 |
| Agent 框架 | **LangChain** | 组织模型调用、工具调用及检索增强生成（RAG）问答。 |
| 流程编排 | **按需使用 LangGraph** | 在需要显式执行状态、复杂分支、检查点或人工中断与恢复时引入相应能力。 |

模型、embedding、存储组件、桌面 UI 及依赖版本将在后续选型中逐步确定。详细选型理由和模块设计将整理到项目文档中。

规划采用单 Agent 连接政策检索、原文读取和订阅管理工具；定期采集、更新检测及提醒由独立任务流程执行。

## 首个里程碑

- [ ] 确定杭州电子科技大学官网的公开栏目和资料范围。
- [ ] 整理 5–10 份有效政策，记录标题、发布日期、采集时间和原文链接。
- [ ] 支持检索这些政策，并对少量问题给出附带原文依据的回答。
- [ ] 对资料中找不到答案或适用范围不明确的问题说明无法确定。
- [ ] 整理首批测试问题、对应依据和测试结果。

完成以上流程后，再逐步扩展栏目与文档规模，实现版本检测、订阅提醒、桌面交互和异常恢复，并按项目验收指标测试。

## 协作开发

技术选型和范围调整先共同讨论并记录；具体任务通过 Issue 跟踪，详细设计和资料清单放入项目文档。
